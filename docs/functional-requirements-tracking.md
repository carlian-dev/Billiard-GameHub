## 1. How Tracking Works

- Each row corresponds to one official functional requirement from the approved GameHub requirements source.
- `Requirement ID` matches the approved source exactly.
- `Requirement` preserves the approved meaning; do not redefine it here.
- `Status` tracks progress (e.g., `Not Started`, `Planned`, `In Progress`, `In Review`, `Done`).
- `Assignee` tracks ownership (Carl / PJ / JAM / JAZ / Unassigned).
- Workflow per requirement: Identify code → Understand → Inspect → Plan → Wait for approval → Implement → Test → Report → Commit → Push → PR → Carl review → Integrate.
